## Sprint 2 - development notes

#### Aseke09 | for 2026-05-27 (lazy coders team)

- **What was done:** 
- Set up `server/server.js` as an Express proxy server for CommerceTools API
- Fixed `dotenv.config()` to correctly resolve `server/.env` using `import.meta.url` (ES modules)
- Added `concurrently` to run Angular dev server and proxy server simultaneously with `npm run dev`
- Created `server/.env.example` with placeholder values for team onboarding
- Updated `.gitignore` to exclude `server/node_modules` and `server/.env`
- Created `src/environments/environment.development.ts` required by Angular build configuration

- **Problems:** 
* `dotenv.config()` was not picking up env variables because `.env` lives in `server/` but the process runs from the project root;
* `server/node_modules` was not excluded from git, risking committing hundreds of dependency files;
* `server/.env` with real API secrets was not gitignored and would have been pushed to GitHub;
* Angular dev server failed to start because `src/environments/environment.development.ts` was missing despite being referenced in `angular.json`;
- **Solutions:** 
* fixed `dotenv.config()` to use `import.meta.url` + `dirname` to resolve the path relative to `server.js` itself;
* added `server/node_modules` and `server/.env` to `.gitignore`;
* created `server/.env.example` with placeholder values for safe team sharing;
* created the missing `environment.development.ts` file to match the Angular build config;
- **What I learned:** 
* ES module projects cannot use `__dirname` directly — need `fileURLToPath(import.meta.url)` to get the file's directory;
* `.gitignore` patterns with a leading `/` only match the root level — nested folders need their own explicit entries;
* Angular 17+ serves static assets from `public/` at the root URL, not `src/assets/`;
- **Plans:** 
* connect Angular frontend to the proxy server API endpoints;
* implement real product data fetching from CommerceTools via the proxy;
